## 1. 开始条件与交付规则

先确认架构及待决项；01/02 设计通过不代表代码存在。纯组件可先用明确测试依赖开发，数据库和真实链路集成必须等待相应实际验收。不得用 Mock 仓储或 Mock LLM 宣布全部验收。

不执行订单、退款、RAG。Stub 仅测试/验收装配，生产缺能力明确失败。每步记录代码范围、命令结果、未验证项及下一步门禁，不按写完代码计完成。

## 第一步：冻结集成契约

- 目标：统一数据/运行/事件接口，避免开发者二次架构设计。
- 模块：execution/models、WorkflowManager 接口、Context、预算和事件契约。
- 前置：本阶段审核；02 修订已明确。
- 步骤：核对 Principal/SessionBinding/AdmissionResult；确认 hash 与最终 ID、可信 run.user_id、组合外键、reconciling；固定任务/claim/结果结构；登记 01/02 未实现项；关闭 workflow 新建命令门禁，落实已明确的 SSE/JSON 双媒体响应。
- 局部验证：契约与状态映射评审、构造/拒绝用例。
- 完成：无 ID 循环或状态歧义；未定公开协议不可直接实现。
- 后继：第二、三、四步可按依赖准备。

## 第二步：Supervisor 核心与路由

- 对应：3.1.1～3.1.4。
- 模块：contracts、supervisor、Prompt、transfers。
- 前置：01 内部契约，第一步模型调用接口。
- 步骤：action 组合→上下文筛选→通用澄清修复→业务续接→切换/放弃→有界错误纠正；使用可注入调用入口。
- 验证：实际节点+可控模型，两轮澄清、擅改目标、非法组合、两次格式失败、task 清理。
- 完成：无业务副作用、无无限重试、身份不由模型改变。
- 后继：第三步主图；正式预算接线在第七步。

## 第三步：主图与 Stub 装配

- 对应：3.2 全部任务。
- 模块：builder、router、公共 nodes、wrapper、测试 Stub。
- 前置：第二步决定契约；Stub 可提前准备。
- 步骤：注入模型和 Saver→接任务控制出口→验证显式映射/config→受控专业分支→实际 builder 路由测试。
- 验证：各有限目标、needs_input/rejected/failed、错 run 结果、私有消息过滤、缺依赖。
- 完成：唯一公开回复出口，生产不能默认启用 Stub，实际图拓扑通过。
- 后继：第五、六步执行接线。

## 第四步：预算核心和持久任务模型

- 对应：3.3.1、3.4.1～3.4.2。
- 模块：execution models/budget、新迁移、配置。
- 前置：第一步；持久验证等待 02 实际验收。
- 步骤：定义任务输入、claim 和结果→预算记录及预留→原子检查/结算→未知和未结算处理→迁移集成。
- 验证：约束、事务回滚、重复预留、并发计量、跨 run 不重置。
- 完成：Runtime 不会先裸跑模型再补预算；任务输入和安全上下文可重建。
- 后继：第五步。任务模型与预算算法可独立开发，迁移统一编号串行合并。

## 第五步：原子受理与独立任务

- 对应：3.3.2～3.3.3。
- 模块：Service、WorkflowManager、ExecutionManager、仓储。
- 前置：01 公共模型、02 身份/事务/查询验收，第三四步。
- 步骤：可信绑定→同事务写 run/任务/预算关联→提交后通知→扫描 queued→原子 claim→并发上限→Runtime 调用→版本/claim 状态收敛。
- 验证：事务中途失败、提交后丢通知、重复通知/受理、调用方退出、跨用户、领取竞争。
- 完成：执行不属于 HTTP；受理后可查询且输入不丢失。
- 后继：第六步快照与故障；第八步 Broker 可先独立测试。

## 第六步：基础 Checkpoint、互斥与故障

- 对应：3.3.4～3.3.5。
- 模块：checkpoint 资源、Runtime、builder、执行器实例控制。
- 前置：第五步、02 真实数据库及持久绑定。
- 步骤：PG Saver 初始化/注入→绑定 thread→互斥与单实例限制→普通/澄清状态装配→启动扫描→安全中断识别→关闭流程。
- 验证：同 thread 串行、跨会话并发、普通续接、queued 重启、running 崩溃、快照/元数据窗口、锁连接丢失、迟到结果、实际 interrupt paused。
- 完成：queued 可继续；运行中不盲重放；等待与核对占槽；资源释放；不声称审批 resume 完成。
- 后继：第七、八步完整治理和输出。

## 第七步：全面预算与超时接线

- 对应：3.4.3～3.4.5、3.1.5 的治理部分。
- 模块：模型入口、Supervisor、Budget、受控工具接口。
- 前置：第四步；跨 run 集成等待第五六步。
- 步骤：所有模型调用接预算→SDK 重试配置→纠正计次→总期限与单次超时→Token usage/上界→工具预算接口→故障预留保存。
- 验证：次数/Token/时间耗尽、usage 缺失、超时、纠正重试、澄清跨 run、重启未结算。
- 完成：每次调用可追踪，未知不零计、不自动退额度，剩余额度不足不推进。
- 后继：正式执行入口开放前必须通过此步；后续 4.3 复用工具接口。

## 第八步：公共事件、订阅和 HTTP

- 对应：3.5 全部任务。
- 模块：Projector、Broker、Route/Service、状态结果存储、OpenAPI。
- 前置：01 版本协议、第五至七步；新建命令表达门禁关闭，双媒体响应模型就绪。
- 步骤：白名单投影→有界队列→首订阅/调度协调→断开清理→200 JSON 重复响应→重连授权/先注册后查状态→持久公开结果查询→唯一终态。
- 验证：真实 ASGI/HTTP 断开仍执行、慢消费者溢出、注册/完成竞争、终态一次、敏感事件不泄漏、重复不重执行、重连不重放。
- 完成：查询拿得到公开终态结果；Broker 不拥有任务；SSE 与数据库状态语义一致。
- 后继：第九步。Broker 纯组件可与第五六步并行，生命周期接线必须等待稳定。

## 第九步：真实模型端到端与阶段验收

- 对应：3.1.5、3.2.5、3.3.6、3.4.5、3.5.5。
- 前置：前八步和 01/02 实际验收；显式真实模型配置；测试专用 Stub 装配。
- 链路：真实请求→可信/受控模拟身份→PG 受理→独立任务→真实模型 Supervisor→实际主图/Stub 专业图→持久快照与预算→SSE→状态结果查询。
- 步骤：三专业路由/未知意图→两类澄清→切换放弃→拒绝/异常/暂停→并发和跨用户→断开/慢订阅/查询→通知丢失/重启/迟到→终态和资源检查。
- 验证：可控故障测试与真实模型调用分别记录，不把付费调用加入默认测试。模型格式与路由真实表现须有证据。
- 完成：01 协议、02 权威关系和 03 治理贯穿；生产无 Stub；未开发业务仍不可用。数据库/真实模型没验证不能标整阶段完成。

## 2. 必须串行和可并行的边界

必须：契约→Supervisor→主图；02 验收→持久受理；原子任务→执行调度→故障边界；预算和生命周期稳定→HTTP 开放；全链路稳定→真实模型整体验收。

可并行：Stub 准备、Budget 算法、Broker 单元组件和协议测试准备。并行不是必须创建子 Agent；同文件修改和迁移合并串行。跨步开发不等于跨步验收。
