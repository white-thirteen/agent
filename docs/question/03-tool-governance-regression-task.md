# 03 工具治理修复后独立回归任务

本任务仅在修复会话完成并由主Agent核对修复报告后派发。沿用[独立QA任务](03-tool-governance-qa-task.md)及冻结D03，核验[原QA报告](03-tool-governance-qa-report.md)、[主Agent裁决](03-tool-governance-main-review.md)、[修复任务](../resume/03-tool-governance-fix-task.md)及届时[修复报告](../resume/record/03-tool-governance-fix-report.md)。

## 必须闭环的问题

1. **03-QA-001 / P2**：在干净子进程实际导入订单数据/领域模块，确认其不反向加载工具、Graph、Runtime；代码方向与冻结设计一致。沿完整Repository/Service→工具适配→Executor/专业图验证已知瞬时故障仍有限重试、每次计数，已知不可重试故障一次失败、不伪装空页/不存在，非预期编程错误及取消不被宽泛吞掉；正常真实PG get/list/隔离/金额保持。
2. **03-QA-002 / P3**：实际工具链保存的call_records明确含可信origin/run_id，不从raw_args取值；不同Run区分，原call/id/name/raw_args及规范参数/结果关联不丢失。观察重进复用记录、稳定消息及预算，父图/公开SSE不新增私有记录。

## 回归范围与证据

- 独立审查修复diff及新增测试可信度，不能只复述修复方自测结论。运行受影响原独立补测并按问题增加必要的仓库外验证；不修改业务代码/仓库测试/配置/依赖。
- 运行一次最新完整专用真实库回归，报告实际通过/失败/跳过数量。复核原14项门禁受本次修改影响的部分及正式HTTP/资源释放。没有新变化或疑点不反复扩大同一验证。
- 本次修改预计不改变模型Schema、模型路由或健康查询结果。根据实际diff说明原真实模型+PG证据是否仍适用；正常情况下无需重复付费模型调用。若发现必须重新调用才能证明的变化，明确原因并按原少量显式门禁组织，不能默认付费。
- 运行对应Ruff lint/执行代码format；六份既有Markdown format和已接受凭据/密码复用继续单列。
- 真实数据库仅agent_demo_test，核对身份、schema3/checksum，完整Session/订单行集前后比对，事务回滚/精确清理自身数据，不迁移、不写应用库、不重建、不换密。保持默认pytest脱敏/fd捕获，不输出秘密或原始连接异常。
- 主Agent派发前记录修复后受控文件摘要，QA结束后复核未变。保持原无关变更与旧QA/开发报告，不调用Bridge/其他会话，不Commit/Push，不实现04。

## 交付

新增 `docs/question/03-tool-governance-regression-report.md`，逐问题说明复现→修复→独立验证证据/结论，记录命令、实际测试数字、数据清理、源码保护、受影响矩阵、原真实联调证据适用性及新问题。新问题沿03-QA-003递增，提供等级/代码与设计依据/复现/影响。保留原QA报告原文。

结论只能建议关闭或继续整改，由主Agent最终复核问题及技术验收，03正式验收和04切换仍由用户决定。结束回复报告路径、通过情况、关闭建议及遗留。
