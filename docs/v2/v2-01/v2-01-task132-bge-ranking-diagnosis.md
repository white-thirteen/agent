## 实现核对

- [输入与推理](../../../app/knowledge/reranker.py)按「原始 Query / 标题、章节、完整正文」组成 pair，开启特殊 token，禁用截断，任一 pair 超过 512 时整次失败。预检后保留同一份 token IDs 做 padding 和前向。用本地固定 Tokenizer 重新计算上表，两题分别为 41–81 与 48–90 token，没有触发边界。标题可能在章节路径里再次出现，这与冻结输入格式一致。本轮没有单独改变标题或章节做模型消融，因此未证明重复标题对结果的影响。
- 固定 BAAI/bge-reranker-base revision `2cfc18c9415c912f9d8155881c133215df768a70`，部署形式为 CPU、离线、safetensors、XLM-R 单输出分类模型、eval 模式。实际重算权重 SHA256 为 `ced967c45fd1902eb92716c9ceeca7c95a936770ea9db611f5a841b926e33fbd`，Tokenizer JSON 为 `9eb652ac4e40cc093272bbbe0f55d521cf67570060227109b5cdc20945a4489e`，与真实验收记录一致。模型的配对调用方式与[官方模型卡](https://huggingface.co/BAAI/bge-reranker-base)一致。
- [应用排序](../../../app/knowledge/retriever.py)与[评测排序](../../../scripts/verify_v2_01_quality.py)均将输入顺序与输出 logits 严格一一对应，分数最高优先。BM25 的负分升序属于另一条链路；RRF 只用各路名次，BGE 使用原始 logits 作自身排序。不同得分空间没有相加。现有证据支持相关性打分偏差被全窗口改序放大，未定位代码实现错误。
