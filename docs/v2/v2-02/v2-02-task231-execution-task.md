# Task 2.3.1 执行边界

本任务在2.2.2独立QA与主复核通过后启动，执行冻结设计，不增加Task或改变验收指标。开发须完成实现、自测和完整交付，不能以调查或局部代码结束；真实阻塞按项目规则报告。

## 模型输入与历史注入

- ContextBuilder保持纯构建，无文件、数据库或模型调用副作用。完整输入预算包括可信Prompt、实际完整工具Schema或结构化输出Schema、当前Task全部必需消息及私有工具历史、当前业务事实/Evidence和输出预留。不得沿用最近12条的截断来丢弃必需消息。
- 专业输入的messages仍只含当前Task，历史通过独立字段显式传递，不进入task_message_ids。低信任历史不能改写身份、原调用/审批/目标或当前业务事实；Knowledge历史不作为Evidence，也不扩大原检索Query来源。
- Checkpoint有ContextRef则读取其固定版本，无ref的恢复按V1；禁止读取最新发布摘要覆盖旧绑定。必要的运行内压缩只用当前Run额度，保存输入哈希、来源和实际注入范围，不裁剪父图或推进会话版本。
- 当前Task或必要事实本身放不下时明确失败或澄清。以完整交互加入历史；精确/估算计数与供应商使用量分别标示。

## Runtime维护与生命周期

- 正式受理前只读；节点前构建；正常安全入口采纳；任务后维护按冻结时序分别接线。业务结算及结果发布不等待摘要成功，也不因维护失败反向撤销。
- 同会话使用现有Runtime执行权互斥，有限执行器有生命周期和关闭处理。澄清、审批、未知结果、resume/reconcile和关闭不启动维护或压缩。
- 只有已确认安全的完成历史可以归档。Graph元数据task_status使用TaskStatus值，PublicInteraction现有契约使用枚举名，边界显式映射，不凭文本推断。缺少可信元数据的旧历史保留，渐进迁移在2.3.2验收。
- 运行内压缩发生时当前Run可能是RUNNING，但对象仍是已完成历史；不得伪装整个会话COMPLETED来调用维护入口。
- 维护旧claim恢复必须证明旧执行者已消失且取得会话独占权，不能仅因某UUID不在当前内存就抢占活跃claim。沿用单进程约束，不扩建通用租约或调度平台。

## 偏好控制与旧Memory退出

- 新请求移除MEMORY_MANAGE路由及旧子图装配；原严格聊天偏好命令在LLM前返回明确迁移提示。旧枚举仅保留历史读取，不伪造新Task来执行偏好。
- 结构化读、mutation及原operation状态入口经过同Policy/Executor。可信控制上下文保存真实command_id，不填假Task、Run、Agent。沿用Manager/Store、两字段、权限、revision、幂等和unknown语义。
- Store写前持久PREPARED/EXECUTING回执，响应丢失按原operation核对；Store已写而回执失败可恢复。未知操作未解决时阻止同用户后续写入，不能因当前值未变化断定未执行。
- last_mutation显式区分旧Task来源与新控制命令，旧记录不批量改写。旧活动/澄清/未知Memory任务未处理时禁止切换，不删除恢复路径强行上线。
