## 已确认缺陷

临时独立QA探针首次在Windows默认Proactor下直接调用psycopg连接，InterfaceError的pytest异常回溯展示了原始连接kwargs中的真实密码。后来修正Selector使探针通过，但旧输出的暴露已发生。现有生产SafePoolLogFilter和Settings的SecretStr不能独立保护测试回溯中驱动内部展开的参数。

## 修复要求

1. 先用完全虚构的密码和受控异常复现，定位最小有效边界，避免真实凭据失败注入。
2. 在工程常规测试入口修复该类异常、捕获日志/标准输出中的凭据回显。考虑测试URL、应用URL及包含密码的连接kwargs/URI，保留测试失败、错误类别、文件/行号和足够诊断信息。默认安全，避免仅靠每次人工选择--tb=no或把失败变为通过/跳过。
3. 原事件也涉及仓库外临时QA文件通过项目pyproject运行。给出明确、可验证的安全测试调用方式，确保该方式对类似外部探针生效。使用少量必要逻辑和回归测试，避免通用秘密管理框架、全仓重构或新依赖。
4. 用虚构凭据覆盖实际pytest失败报告及捕获日志/输出。验证密码值与连接串中密码不可见，非敏感错误类别和失败退出码保留。明确实际支持的输出/报告路径和边界，额外输出后端按需验证。
5. 原生产日志防护如需变更须基于实际证据最小修改。不要把异常原文、真实URL、密码、headers或原始敏感回溯写入工具输出/报告。真实环境复核使用脱敏输出，PG仅允许现有专用agent_demo_test和隔离/回滚/精确清理，无应用库写入、迁移升级或基础设施操作。
6. 使用项目.venv，先受控回归再必要完整开发回归及定向Ruff。保留用户原有修改，主Agent维护docs/question/02-agent-runtime-main-review.md，其他角色报告保留历史语境。不得调用其他会话，不Commit/Push或启动03。
